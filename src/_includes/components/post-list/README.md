# Blog and post list

Covers `pages/blog.liquid`, `category.liquid`, `tag.liquid`, and the shared `components/post-list/` card markup.

- `blog.liquid` paginates the `blogPages` collection (newest first) at `site.postsPerPage` (default 10) per page, one output page per entry. Page 1 is `/blog/`, page 2+ is `/blog/page/N/`. The numbered nav is the [`pagination`](../pagination/README.md) component.
- **`src/pages/` directory data wins over a template's own plain `permalink:`.** `pages.json` sets `eleventyComputed.permalink` for every file in that directory; a plain `permalink:` string in `blog.liquid` itself was silently ignored (all pagination pages resolved to the same `/blog/`, causing a duplicate-output build error). The fix is to override it as `eleventyComputed.permalink` in the template's own front matter too — a more specific `eleventyComputed` key beats the directory-level one, but a plain `permalink:` does not. Same trap applies to any other computed directory-data key (currently just `permalink`, in both `pages.json` and `posts.json`). This is also why `category.liquid`/`tag.liquid` live at the site root instead of under `pages/` — they need their own pagination/permalink and would otherwise inherit this same clobbering.
- Featured images: set `image: <path-relative-to-src/images/>` in a post's front matter; `post-list.liquid` runs it through `{% responsiveImage %}` and links it to the post, shown above the title. Optional — posts without `image` just skip it.
- Categories: set `categories: [...]` (array of strings) in a post's front matter. Shown as filled pill links under the title, each pointing to `/blog/category/<slug>/`.
- Tags (for WordPress-imported content, which usually has both taxonomies): set `tags: [...]` in a post's front matter. Shown as lighter `#tag` links pointing to `/blog/tag/<slug>/`. **`tags` is also Eleventy's own collection mechanism** — `posts.json` sets `tags: "posts"` at the directory level, and Eleventy's data cascade merges (not overrides) `tags` arrays, so every post's real `post.data.tags` is actually `["posts", ...whatever the post added]`. Always run it through the `filterTagList` filter (`helpers/posts.js`/`filters.js`, strips the reserved `"posts"` entry) before displaying or grouping — this is the same `filterTagList` pattern the official `eleventy-base-blog` starter uses, not a one-off hack.
- `blog.liquid`, `category.liquid`, and `tag.liquid` all paginate a precomputed, chunked collection — `blogPages`/`postCategoryPages`/`postTagPages` (`eleventy.config.js`), built by the shared `paginateGroupedPosts()` helper (`helpers/posts.js`) at `site.postsPerPage` — one entry per (term, page) pair, each carrying `{ term, posts, pageNumber, totalPages }`. `pagination: { data: ..., size: 1, alias: ... }` then generates one output page per entry. Eleventy's built-in `pagination.size` can't read site data, and its `pagination.href` isn't shaped for paginating within a group, which is why all three use this shape.
- `partials/post-archive.liquid` is the shared body (post-list + the `pagination` nav) all three include, parameterized by `posts`/`pageNumber`/`totalPages`/`term`/`basePath` — extend that one file, not each template, if the archive layout changes.
- `blog.liquid`, the category archive, and the tag archive all share `components/post-list/post-list.liquid` for the actual card markup — extend that one file rather than duplicating post-card markup if a third listing view gets added later.
- **Post titles are real headings.** `post-list.liquid` wraps each title in `<h2>` by default; pass `headingLevel: 3` when the list sits under an h2 (the home page's "From the blog", the author page's "Blog posts"). Keep the level one below the section's heading so the outline never skips. `.post-list-title` keeps the card at `--step-1` rather than the full h2/h3 size; case, letter-spacing, weight and `text-wrap: balance` come from the global heading styles in `_type.css`. `post-archive.liquid` doesn't pass a level, so blog, category and tag archives (h1 page title) get h2.
